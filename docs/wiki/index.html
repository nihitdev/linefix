Documentation

linefix check README.md

Installation

Linux and macOS

curl -fsSL https://raw.githubusercontent.com/nihitdev/linefix/main/install.sh | sh

The checksum-verifying installer detects Linux or macOS and AMD64 or ARM64, then installs to ~/.local/bin.

Windows

irm https://raw.githubusercontent.com/nihitdev/linefix/main/install.ps1 | iex

Run in PowerShell. It installs per-user and adds the installation directory to PATH without requiring Administrator privileges.

Command reference

CommandBehavior
linefix lf <file>Convert CRLF to LF
linefix crlf <file>Normalize and convert LF to CRLF
linefix check <file>Print LF, CRLF, Mixed, or No line endings
linefix --versionPrint the build version

Exit codes

  • 0 — success
  • 1 — file or conversion error
  • 2 — invalid arguments

How it works

linefix reads a regular file, samples it for likely binary content, converts the bytes in memory, and writes only when the result differs. Every LF is classified as CRLF when immediately preceded by a carriage return, or LF otherwise.

For CRLF output, existing CRLF is normalized first. This ensures each newline is expanded exactly once and avoids accidental \r\r\n.

Safe replacement

  1. Create a temporary file beside the original.
  2. Apply the original permission bits.
  3. Write and sync the converted content.
  4. Replace the original path.

Empty files, files without a trailing newline, and already-normalized files are left structurally unchanged.

Development

Go 1.22 or newer is required. linefix has no third-party dependencies.

git clone https://github.com/nihitdev/linefix.git
cd linefix
gofmt -w .
go vet ./...
go test ./...
go build .

Keep output concise, preserve bytes outside the requested change, and add focused tests for behavior changes.

Releasing

Push an annotated semantic-version tag after CI passes:

git tag -a v0.2.0 -m "linefix v0.2.0"
git push origin v0.2.0

The release workflow tests, cross-compiles six targets, packages each executable with the README and GPL license, generates SHA256SUMS, and publishes the GitHub Release.

Troubleshooting

Command not found

Add ~/.local/bin to PATH on Unix. On Windows, open a new terminal after installation to pick up the updated user PATH.

Binary-file rejection

NUL bytes or a high proportion of control bytes trigger the safeguard. Convert legitimate text in unusual encodings to UTF-8 first.

No line endings

This is expected for an empty file or a file containing no LF or CRLF sequence. Conversion leaves it untouched.
